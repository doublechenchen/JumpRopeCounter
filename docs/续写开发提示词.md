## 二、项目现状

**APP 名称**：跳绳计数（applicationId: `com.cc.jumprope`，当前版本 v1.1 / versionCode 2）

**已实现功能**：

- 首页：运动员名字输入（自动保存历史名字下拉候选）、两种模式入口、成绩记录入口
- 计时模式：固定时长（分/秒可设）倒计时数个数；计数模式：固定目标个数正计时
- 点「开始」后全屏 3→2→1 倒计时（语音同步），结束后自动开始计数
- 摄像头 AI 自动计数：CameraX 前置摄像头 + ML Kit 姿态识别（`pose-detection:18.0.0-beta5`，离线模型），也可关闭用「手动 +1」
- 播报：每跳 1 个短促提示音（ToneGenerator）；每 10 个报数；计时模式最后 10 秒报「还剩十秒」；计数模式还剩 10 个时报已用时间；结束播报成绩；破纪录加播「新纪录」
- 成绩系统：SharedPreferences + JSON（`ScoreStore.kt`），按「运动员+模式+目标档位」记录历史最佳；成绩记录页展示各档最佳与全部记录，可清空；v1.1 起带防损坏保护（数据解析失败时自动备份原文到 `records_backup` 键并当空表处理，不崩溃不连锁丢失）
- 暂停/继续/提前结束/再来一次；计数期间屏幕常亮

**已验证性能**：姿态识别 30fps 满帧无丢失；30 秒实测 68 个计数与离线复核 71 个波形吻合度 96%（差异仅在开局调整站位阶段）；语音播报延迟约 30ms。

## 三、关键技术决策（不要回退）

| 决策 | 原因 |
|---|---|
| 四点融合特征（左肩+右肩+左髋+右髋 Y 坐标求和）+ 3 帧均值滤波 + 逐周期峰谷检测 | 参考天天跳绳专利方案（CN113706507A）。单点方案已验证失败：肩膀信号太弱、脚踝在 BlazePose 快速模式下抖动大 |
| 内置 27+1 个 AI 预生成语音片段（res/raw/*.mp3）+ SoundPool 预加载 | 小米澎湃 OS 国行无 TTS 引擎（tts_default_engine 为 null），系统 TTS 完全无声；SoundPool 解决 MediaPlayer 加载延迟不同步问题 |
| 中文数字拼接播报（cnParts 函数，0~9999） | 成绩数字是动态的，无法全部预生成 |
| 语音片段已用 ffmpeg 裁剪首尾静音 | 否则播报有明显延迟感 |

**跳跃判定核心参数**（`CountActivity.kt` 顶部 companion object）：

- `AMP_MIN_RATIO = 0.05f` — 最小有效振幅（相对躯干长度），漏记调小、误记调大
- `JUMP_REFRACTORY_MS = 300L` — 两次计数最小间隔

## 五、小米手机的坑（已踩过）

1. **USB 安装**：adb install 报 `INSTALL_FAILED_USER_RESTRICTED` 时，需在手机 设置→更多设置→开发者选项 打开「USB 安装」（要求登录小米账号+插 SIM 卡），系统有时会自动关掉
2. **无法模拟点击**：`adb shell input tap/keyevent` 报 INJECT_EVENTS SecurityException，UI 测试只能用户手点 + adb 截屏验证（`adb exec-out screencap -p > x.png`）
3. **Git Bash 路径**：adb shell 里的安卓路径会被 MSYS 转换，需先 `export MSYS_NO_PATHCONV=1`
4. **覆盖安装**：debug 与 release 签名不同，互相替换前必须先 `adb uninstall com.cc.jumprope`（会清空成绩数据）

## 九、版本管理、Git 仓库与分发

**GitHub 仓库（公开）**：https://github.com/doublechenchen/JumpRopeCounter

- 本地 git 仓库在 `JumpRopeCounter\`（main 分支），推送凭据已缓存在本机 Git Credential Manager
- **不入库的东西**（已在 .gitignore）：`jumprope.keystore`、`keystore.properties`、`local.properties`、构建产物、APK。换新电脑开发时，clone 后需手动补回 `jumprope.keystore` 和按模板填好的 `keystore.properties` 才能打正式包
- 日常代码更新：在 `JumpRopeCounter` 目录 `git add -A && git commit -m "说明" && git push`

**版本规则**：

1. 每次发布在 `app/build.gradle` 把 `versionCode` 加 1、`versionName` 改成人看的号（v1.0 → v1.1 → …）；系统只凭 versionCode 判断新旧
2. **换签名 = 只能卸载重装，成绩全清空**（2026-10-16 19:21 debug→release 换装时发生过一次，A 用户记录因此丢失，属一次性事件）

**发新版标准流程**（装到自己手机 + 发布到 GitHub）：

1. 升 `versionCode` / `versionName` → `assembleRelease`（同密钥签名）
2. 本机安装：`adb install -r` 覆盖安装（同签名即升级，**成绩数据保留**，可用 `dumpsys package com.cc.jumprope | grep firstInstallTime` 验证，时间不变即升级成功）；产物另存为 `跳绳计数器-vX.X-正式版.apk` 存工作目录
3. `git add -A && git commit && git push` 更新仓库代码
4. 建 GitHub Release：运行工作目录的 `upload_release.py`（改脚本里的版本号；它会从 Git Credential Manager 取 token，调 GitHub API 建 Release 并上传 APK）。**资产文件名固定用 `JumpRopeCounter.apk`**，这样永久下载链接永远指向最新版：
   `https://github.com/doublechenchen/JumpRopeCounter/releases/latest/download/JumpRopeCounter.apk`
5. 若 README 的版本相关内容有变化，一并更新提交

**分发方法**：

- 首选：把上面的**永久下载链接**发给朋友，安卓手机点开下载、文件管理器打开安装，"未知来源"提示选「仍然安装」（非商店 APP 的正常提示）
- 备选：微信/QQ 以「文件」形式发 APK、U 盘、网盘；微信可能把 APK 改名成 `.apk.1`，需在文件管理器改回 `.apk`，或先压成 zip 再发
- 各手机成绩独立保存互不影响；发新版把新链接/APK 再发一遍，覆盖安装即升级
